ParsLingo اپلیکیشن یادگیری زبانِ فارسی‌اولی است که خودم به‌تنهایی طراحی، ساختم و منتشر کردم: یک اپ React Native که واژگان و عبارت‌های فارسی را با معماری آفلاین‌محور، تبدیل متن به گفتار روی دستگاه و سیستم مرور مبتنی بر تکرار فاصله‌دار آموزش می‌دهد. سال اول از مرز ۱۰ هزار دانلود گذشت و امتیاز ۴.۶ ستاره مستقر شد — بدون بودجه‌ی تبلیغاتی، بدون سرور و بدون بک‌اندی که باید نگهش می‌داشتم.

این مطالعه‌ی موردی روایتِ این است که چرا «آفلاین‌اول» و «راست‌چین‌اول» ویژگی‌هایی نبودند که اضافه کنم؛ قیدهایی بودند که کل معماری از دلشان رویید.

## مسئله

یادگیرندگان فارسی از سوی اپ‌های مسلطِ بازارِ زبان‌آموزی بد سرویس می‌گیرند، و دلایل این اتفاق یکدیگر را تشدید می‌کنند.

**پوشش نازک است.** پلتفرم‌های بزرگ یا اصلاً فارسی ندارند یا مثل یک اولویت کم‌اهمیت به آن نگاه می‌کنند؛ محتوای کم و تمرین‌های ژنریک که بی‌اعتنا به کارکرد واقعی زبان‌اند — از خط آن گرفته تا قواعد اتصال حروف و سیستم اعدادش.

**اتصال، مفروض گرفته شده است.** اپ‌هایی که فارسی دارند، اتصال پایدار و سریع را پیش‌فرض می‌گیرند؛ پیش‌فرضی که برای دو گروه از سه گروهِ اصلیِ مخاطب فرو می‌ریزد: یادگیرندگان داخل ایران، که اتصال ناپایدار است و محدودیت‌های مرتبط با تحریم، CDNهای رایج و پرداخت گوگل‌پلی را می‌بندد؛ و اهل دیاسپورا که در مترو و هواپیما رفت‌وآمد می‌کنند.

**راست‌چین، بعداً به ذهن رسیده است.** در اپ‌هایی که اصلاً زحمتش را کشیده بودند، پشتیبانی راست‌به‌چپ به‌وضوح وارونه بسته شده بود: آیکون‌های جهت‌دار آینه نشده‌اند، اعداد فارسی وسط جمله جای خود را به لاتین داده‌اند و تایپوگرافی تمرین‌ها اتصال حروف را می‌شکند. برای زبانی که با خط عربی نوشته می‌شود، این‌ها گلایه‌های تزئینی نیستند؛ خودِ آموزش را غلط می‌کنند.

کاربرانی که برایشان ساختم مشخص بودند: کسی در تورنتو که فارسی را در کودکی در خانه شنیده اما نظام‌مند نیاموخته و حالا می‌خواهد نوسازی‌اش کند؛ مسافری که برای سفری آماده می‌شود؛ و همسری که زبان همسرش را یاد می‌گیرد. هر سه یک چیز می‌خواستند که بازار بهشان نمی‌داد: معلمی جدیِ فارسی که در جیب جا شود و وقتی شبکه نیست، کار کند.

## فرایند

### پژوهش پیش از کد

پیش از نوشتن حتی یک خط اپ، با حدود ۲۰ یادگیرنده در این سه پرسونا مصاحبه کردم. سه یافته همه‌چیز را شکل داد:

- **آفلاین از بازی‌سازی جلو زد.** هیچ‌یک دنبال جدول امتیازات یا آتش‌بازی استریک نبودند؛ تقریباً همه یادگیری در مناطق مرده را توصیف کردند — رفت‌وآمد، پرواز، اینترنت لرزانِ خانه. هر چه اپ می‌کرد، اول باید بدون اتصال کامل کار می‌کرد.
- **راست‌چینِ درست از شمارش ویژگی‌ها جلو زد.** یادگیرندگانی که قبلاً با اپ‌های دیگر کار کرده بودند، همین رفتارهای شکسته را — بی‌آنکه من بپرسم — شرح دادند. اعتماد به اپ با تایپوگرافی ساخته و نابود می‌شد.
- **صدا غیرقابل‌مذاکره بود.** تلفظ، سخت‌ترین بخش فارسی برای انگلیسی‌زبان‌هاست و یادگیریِ فقط‌متنی را «حدس‌زدن» توصیف کردند.

### معماری محتوا

مدل محتوا را پیش از صفحه‌ها طراحی کردم: واحد‌ها درس دارند، درس‌ها تمرین دارند و هر قطعه‌ی آموزشی یک «کارت» است که از زمان‌بندِ تکرار فاصله‌دار عبور می‌کند. محتوا یک‌بار در JSON ساخت‌یافته نوشته می‌شود — قلمِ خودم، بازبینی‌شده توسط گویشوران بومی — و به پایگاه SQLiteای کامپایل می‌شود که داخل اپ منتشر می‌شود. این خط لوله یعنی کارِ محتوا و کارِ کد می‌توانستند موازی پیش بروند و اپ یک منبع حقیقتِ واحد برای محتوای هر درس داشت.

### راست‌چین‌اول، از اولین کامیت

به‌جای آنکه LTR بسازم و «RTL را اضافه کنم»، هر صفحه را با ویژگی‌های منطقی ساختم — `paddingStart` و `marginEnd` و `textAlign: 'start'` — و آیکون‌های جهت‌دار فقط جایی آینه شدند که جهت، بخشی از معنای آیکون بود. اعداد فارسی در بافت فارسی می‌آیند؛ اعداد لاتین در بافت‌های فنی مثل شماره‌ی نسخه می‌مانند. سیستم چیدمان هرگز نمی‌فهمد LTR رندر می‌کند یا RTL؛ اصلاً نیازی به فهمیدن ندارد.

## راه‌حل

اپ با React Native و Expo ساخته شده است، با TypeScript سخت‌گیرانه، و معماری‌اش یک اصل سازمان‌دهنده دارد: **شبکه سازوکار تحویل محتواست، هرگز وابستگیِ زمان اجرا نیست.**

پایگاه SQLite به‌عنوان asset همراه اپ منتقل می‌شود. در اولین اجرا به حافظه‌ی نوشتنی کپی می‌شود و هر به‌روزرسانی محتوایی بعدی به‌شکل بسته‌ی کوچک diff می‌رسد که اپ به‌صورت تراکنشی اعمال می‌کند — پس یک به‌روزرسانی ناموفق یا ناتمام هرگز نمی‌تواند پایگاه را نیمه‌مهاجرت‌شده بگذارد. بعد از آن اولین اجرا، اپ کامل است: درس‌ها، تمرین‌ها، صدا، زمان‌بندی، پیشرفت — همه محلی.

زمان‌بند مرور، الگوریتمی ساده‌شده به سبک SM-2 است که کاملاً روی دستگاه اجرا می‌شود:

```ts
/**
 * Schedules the next review for a card given the learner's answer
 * quality (0–5, standard SM-2 scale). Runs fully offline.
 */
export function scheduleReview(
  card: Card,
  quality: AnswerQuality,
  now: Date,
): Card {
  if (quality < 3) {
    // Failed recall: repetition count resets, card returns soon.
    return {
      ...card,
      repetitions: 0,
      intervalDays: 0,
      dueAt: addMinutes(now, 10),
    };
  }

  const repetitions = card.repetitions + 1;
  const intervalDays =
    repetitions === 1
      ? 1
      : repetitions === 2
        ? 3
        : Math.round(card.intervalDays * easiness(card));
  return {
    ...card,
    repetitions,
    intervalDays,
    dueAt: addDays(now, intervalDays),
  };
}

function easiness(card: Card): number {
  // Clamp between 1.3 and 2.5 — the classic SM-2 bounds.
  return Math.min(2.5, Math.max(1.3, card.easeFactor));
}
```

چون زمان‌بند تابعی خالص روی یک `Card` تغییرناپذیر است، آزمودنش بی‌زحمت است و هیچ وابستگی‌ای به منطقه‌ی زمانی، فراخوانی شبکه یا ساعت دستگاه جز آرگومانِ `now` که از بیرون می‌آید ندارد.

## نتیجه

ParsLingo در سال اول از مرز ۱۰ هزار دانلود گذشت، امتیاز ۴.۶ ستاره را نگه داشت و هزینه‌ای برای اجرا نداشت — نه سروری، نه صورتحساب CDN، نه اتصال به درگاه پرداخت. همان قیدهایی که شبیه محدودیت به نظر می‌رسیدند، خودِ محصول شدند: اپی که در متروی تهرانِ بی‌سیگنال کار می‌کند، فارسی را همان‌طور که واقعاً نوشته می‌شود رندر می‌کند و تلفظ را بدون یک بار تماس با سرور آموزش می‌دهد.

درسی که از این پروژه با خودم بردم این است که «آفلاین‌اول» و «راست‌چین‌اول» ویژگی‌هایی نیستند که بعد از ساخت اپ به آن بچسبانی. تصمیم‌های معماری‌ای هستند که باید پیش از نوشتن اولین صفحه گرفته شوند، چون وقتی به مرحله‌ی اضافه‌کردنشان رسیده باشی، دیگر اضافه‌شان نمی‌کنی — از نو می‌نویسی.
